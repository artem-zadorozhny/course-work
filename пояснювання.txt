Для пояснювальної записки до курсової роботи архітектуру та принцип роботи твоєї бази даних потрібно описати через професійну термінологію.
Ось готовий структурований матеріал, який ти можеш перенести у розділ «Проєктування та розробка бази даних» або «Обґрунтування вибору технологій».

1. Яка СУБД використовується та чому?

У проєкті використано реляційну систему керування базами даних (СУБД) SQLite.
• Принцип автономності (Serverless): На відміну від класичних СУБД (як-от MySQL або PostgreSQL), SQLite не потребує окремого запущеного сервера-процесу. Уся база даних, разом із таблицями, індексами та самими даними, зберігається в одному компактному файлі library.db прямо в папці проєкту.
• Обґрунтування вибору: Це забезпечує максимальну портативність додатка (проєкт можна перенести на будь-який комп'ютер на флешці без додаткового налаштування серверів баг-трекінгу чи баз даних) та високу швидкість читання даних.

2. Логічна структура та зв'язки (Дата-модель)

База даних побудована за реляційним принципом (дані розбиті на логічні таблиці, що пов'язані між собою через ключі). Спроектовано 3 взаємопов'язані таблиці:
1. books (Каталог книг): Хранить первинну інформацію про кожну книгу (автор, назва, рік, жанр, загальна кількість примірників). Головне поле — id (унікальний цифровий ідентифікатор, Primary Key).
2. users (Облік читачів): Хранить реєстраційні дані користувачів (ім'я, унікальний email та пароль). Поле id є Primary Key.
3. loans (Облік видачі / бронювань): Це єдина связуюча таблиця, яка реалізує зв'язок типу «Один до багатьох» (One-to-Many): один читач може забронювати кілька книг. Вона містить:
	• Поле bookId — посилається на id конкретної книги (це Foreign Key — зовнішній ключ).
	• Поле email — посилається на email користувача, який зробив замовлення.
	• Дати видачі та граничного строку повернення книги.

3. Покроковий принцип роботи (Як дані ходять по колу)

Взаємодія сайту з базою даних відбувається за класичною трирівневою архітектурою: Клієнт (Браузер) → Веб-сервер (Node.js) → База даних (SQLite).

Процес А: Відображення книг (Операція читання - GET)

1. Користувач відкриває сайт у браузері.
2. JavaScript-код на фронтенді (script.js) автоматично надсилає асинхронний мережевий запит (fetch) на адресу /api/data.
3. Сервер на Node.js (server.js) приймає цей запит, підключається до файлу library.db і виконує SQL-запити: SELECT * FROM books та SELECT * FROM loans.
4. SQLite миттєво віддає рядки з таблиць. Сервер пакує їх у формат JSON і відправляє назад у браузер.
5. Фронтенд розбирає цей JSON і за допомогою DOM-маніпуляцій динамічно малює картки книг на HTML-сторінці.

Процес Б: Бронювання книги (Операція запису - POST)

1. Авторизований читач натискає кнопку «Забронювати».
2. JavaScript зчитує id книги та email користувача і відправляє їх методом POST на сервер (/api/loans).
3. Сервер обробляє ці дані й виконує SQL-команду додавання запису:sql
INSERT INTO loans (bookId, email, date, due) VALUES (?, ?, ?, ?);
Используйте код с осторожностью.
4. Новий рядок надійно записується у файл бази даних. Фронтенд отримує сигнал успіху (success: true) і оновлює таблицю «Мої бронювання» на екрані користувача.

4. Терміни для висновку (Що написати в результатах)

«В ході виконання курсової роботи було успішно здійснено перехід від статичного збереження даних у локальному сховищі браузера (localStorage) до повноцінної архітектури клієнт-серверної взаємодії. Інтеграція СУБД SQLite дозволила забезпечити цілісність даних (Data Integrity) за допомогою реляційних зв'язків та унікальних ключів, а також гарантувати персистентність (постійність) збереження інформації незалежно від сесії конкретного браузера користувача».
